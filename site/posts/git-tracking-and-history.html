저장이라는 말 하나로 묶지 않기

add와 commit을 비슷하게 생각했던 부분을 ‘변경 선택 → 버전 기록 → 원격 공유’로 나누어 정리했다.

목적명령
다음 커밋의 변경 선택git add 파일명
선택한 내용을 커밋으로 기록git commit -m "변경 설명"
원격에 커밋 공유git push

파일은 add 후에도 작업 폴더에 남는다. 커밋 메시지도 별도로 저장할 파일이 아니라 그 변경을 설명하는 내용이다.

.gitignore는 이미 추적 중인 파일을 자동 해제하지 않는다

파일의 존재 여부, Git의 추적 여부, 무시 규칙 적용 여부를 나누어 보아야 했다. git status --ignored, git ls-files 파일명, git check-ignore -v 파일명은 서로 다른 것을 확인한다. check-ignore에 출력이 없다는 것만으로 모든 상태를 결론 내리지 않는다.

인덱스에서 제외하는 일과 과거 이력의 비밀 정보를 지우는 일도 별개다. 이미 노출된 인증 정보는 ignore 규칙만 추가해서 해결되는 문제가 아니다.

reset과 revert도 결과가 다르다

일반적인 브랜치 전체 reset에서는 soft·mixed·hard에 따라 브랜치가 가리키는 커밋, 인덱스, 작업 파일 중 어디까지 맞추는지가 다르다. hard는 미커밋 변경을 잃을 수 있어 실제 프로젝트에서 시험하지 않는다. revert는 지정 커밋의 변경을 취소하는 새 커밋을 만든다.
