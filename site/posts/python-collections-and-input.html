리스트에서 기존 칸 수정과 추가는 다르다

원소가 세 개인 리스트의 인덱스 3에 대입하면 새 항목이 생기는지 질문했다. 기존 TIL의 AI 정정에서는 일반 인덱스 대입은 기존 항목 수정이며 새 원소는 append나 extend로 추가한다고 구분했다.

표현구분
items[i] = value기존 위치의 값 변경
items.append(value)원소 하나 추가
items.extend(values)iterable의 원소들을 추가

딕셔너리에서 중복되지 않는 것은 키다

서로 다른 키가 같은 값을 가질 수 있다는 점, keys()·values()·items()가 각각 뷰를 반환한다는 점을 정리했다. get()은 값을 반환하며 화면 출력 자체를 담당하지 않는다.

input의 문자열과 숫자 검증

input()의 반환값은 문자열이므로 숫자가 필요하면 별도로 변환한다. 문자열을 숫자로 바꾸는 단계의 실패와 변환한 숫자의 범위 검사는 다르다. 잘못된 입력 처리 방법을 질문했지만 수정·실행 결과까지 확인된 것은 아니다.

과제 코드를 남기며 발견한 확인 과제

가위바위보·할인 계산·메뉴 선택 등의 코드가 TIL에 남아 있고, 가위바위보 판정을 반복 검수 요청한 기록도 있다. 다만 두 검수 사이의 정확한 코드 차이나 입력별 테스트 결과는 남아 있지 않다. 가위바위보의 잘못된 입력 처리와 반복문의 종료는 별도 실습에서 확인할 항목으로 둔다.

Git 브랜치 병합에 대한 질문도 같은 날 남겼다. 브랜치 이름이 값의 우선권을 자동 결정한다는 규칙은 없으며, 실제 병합·충돌 해결 성공은 기록에서 확인되지 않았다.
