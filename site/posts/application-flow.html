다시 만들 수 있으려면 뼈대를 알아야 했다

AI와 함께 결과물을 만드는 경험이 쌓여도, 다음 작업에서 같은 구조를 스스로 설명할 수 있는지는 별개의 문제였다. 그래서 지금까지 만든 것들을 공통 로직 관점에서 분석해 달라고 요청했다.

내가 먼저 정리한 흐름은 ‘입력 → 데이터 전처리 → 조건 → 검증 → 출력’이었다. 실제 애플리케이션에서는 여기에 어떤 단계가 추가되는지 궁금했다.

게임도 같은 구조일까

일반 프로그램과 게임의 차이, 게임 최적화가 이루어지는 방식을 이어서 질문했다. 기존 TIL에는 AI가 저장·상태·실행·피드백, 게임 루프·이벤트·렌더링, 병목 측정의 관점으로 설명했다는 요약이 남아 있다.

이것을 내가 게임에 구현하거나 프로파일러로 확인한 것은 아니다. 현재 확인되는 것은 구조를 비교하려고 질문했다는 학습 과정이다.
