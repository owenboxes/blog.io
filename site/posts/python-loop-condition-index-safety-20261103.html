반복 조건과 접근 조건을 나누기

트럭 시뮬레이션에는 대기 트럭 목록과 다리 위 상태가 함께 등장한다. 두 목록은 서로 다른 시점에 비어질 수 있다.

대기 트럭이 없어도 다리에 트럭이 남아 있다면 이동은 계속되어야 한다. 하지만 반복을 계속한다는 이유만으로 대기 목록의 첫 원소에 접근해도 되는 것은 아니다.

python
while waiting or sum(bridge) > 0:
    # 반복 본문 안에서 waiting[0]을 읽기 전에는
    # waiting이 비어 있지 않은지 별도로 확인해야 한다.
    pass

위 코드는 조건의 역할만 보여 주는 설명 조각이다. 상태를 바꾸지 않으므로 그 자체로 실행할 완성 예제가 아니다.

빈 리스트와 빈 문자열은 다르다

리스트를 빈 문자열 ""과 비교하는 것은 빈 목록 검사와 다르다. 빈 리스트인지 확인할 때는 해당 리스트의 참·거짓 값을 사용할 수 있다.

python
if waiting:
    next_weight = waiting[0]

대기 목록이 비어 있으면 이 분기의 첫 원소 접근을 건너뛴다. 다리 위 상태가 [0, 0]처럼 빈칸으로만 채워져 있어도 리스트 자체에는 원소가 있으므로 참으로 평가된다는 점도 구분해야 한다.

길이 숫자와 상태 리스트 분리하기

다리 길이는 입력값이고, 다리 상태는 매초 바뀌는 데이터다. 같은 변수에 두 역할을 섞으면 전달받은 길이를 고정 리스트로 덮어쓸 수 있다.

python
bridge_length = 3
bridge = [0] * bridge_length

이 표현은 숫자 길이와 상태 리스트를 나누어 둔다. 다리 칸을 한 칸씩 이동시키는 모델에서는 매 단계 앞칸 하나를 꺼내고 뒤에 트럭 또는 0을 하나 추가해 길이를 유지한다.

검증할 것은 출력뿐 아니라 상태

  • 대기 목록이 먼저 비었을 때 첫 원소를 읽지 않는가?
  • 대기 목록이 비어도 다리 위 트럭은 끝까지 이동하는가?
  • 단계가 끝날 때 다리 상태의 길이가 유지되는가?
  • 입력 리스트를 pop으로 소진하는지, 복사해 사용하는지 의도가 명확한가?

길이 1 이상, 양수 트럭 무게가 각각 허용 무게 이하인 조건을 전제로 한 설명이다. 길이 0이나 허용 무게 초과 트럭은 별도 입력 정책이 필요하다. 이 글은 알고리즘 학습용 설명이며 플랫폼 제출 통과나 학습자의 해결 완료 기록이 아니다.
