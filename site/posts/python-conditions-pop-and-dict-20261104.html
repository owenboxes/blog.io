여러 조건을 적용할까, 하나만 선택할까

for로 항목을 꺼내고 if로 고르는 수업 예제를 기록했다. 여기의 코드는 수업 기록을 재구성한 설명이며, 전부 내가 독립적으로 작성·실행하거나 이해 완료했다는 기록은 아니다.

계란에는 냉장 배송과 파손 주의가 모두 적용된다. if 두 개를 각각 검사하면 두 동작을 실행할 수 있다. 배송 상태 하나에 대응하는 안내를 고를 때는 if·elif로 처음 참인 분기를 선택한다.

python
# 수업 예제를 재구성한 설명 코드
products = ["우유", "유리컵", "사과", "계란"]
for product in products:
    if product in ["계란", "우유"]:
        print(product, "냉장 배송")
    if product in ["계란", "유리컵"]:
        print(product, "파손 주의")

누적 보상인지 하나의 등급을 정하는지 먼저 확인한다. 문장에 나온 단어만으로 분기 구조를 결정하지 않는다.

값으로 지우는 remove와 위치로 꺼내는 pop

index는 값이 처음 나타난 위치를 돌려준다. remove는 같은 값을 찾아 지우고, pop은 지정한 위치의 원소를 제거하면서 반환한다.

python
menu = ["아메리카노", 2000, "카페모카", 2500, "카페라떼", 3000]
i = menu.index("카페모카")
# menu.remove(i)는 값 2를 찾는다. 이 목록에는 없어 ValueError가 난다.
menu.pop(i)
menu.pop(i)
print(menu)

첫 pop 뒤 2500이 같은 위치로 이동한다. 같은 위치를 다시 pop하면 가격을 지운다. i + 1을 지우면 다음 메뉴인 카페라떼가 지워진다. 이 차이는 AI 별도 검수와 사용자 실행 결과를 구분해 기록했다.

enumerate도 순회 중 삭제 문제는 남긴다

enumerate는 카운터와 값을 함께 준다. 기본 번호는 0부터 시작하며 화면용 번호는 start=1로 시작할 수도 있다. 이 번호가 항상 원본 인덱스라는 뜻은 아니다.

원본 목록을 순회하며 삭제하면 뒤 원소가 앞으로 이동한다. 수업 예제에서는 수박주스를 지운 뒤 카페라떼 방문을 건너뛰었다. 이름·가격 두 목록의 대응이 맞아도 모든 항목을 검사했다는 의미는 아니다.

이름과 가격을 연결하는 딕셔너리

python
prices = {"아메리카노": 2500, "수박주스": 5000, "카페라떼": 3000}
print(prices["아메리카노"])

딕셔너리는 메뉴명 키로 값을 찾는다. 없는 키를 대괄호로 조회하면 KeyError가 난다. 앞의 리스트 예제와 가격이 다른 것은 자료형이 아니라 데이터가 다르기 때문이다. 튜터 자료를 기록한 사실을 직접 구현한 성과로 바꾸지 않는다.
