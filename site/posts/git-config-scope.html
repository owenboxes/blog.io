넓게 적용되는 설정이 항상 우선은 아니었다

Git의 system·global·local 설정을 공부하면서 범위가 넓은 것과 우선 적용되는 것을 혼동했다. system은 회사 전체, global은 개인 계정, local은 특정 저장소에 비유해 다시 설명해 보았다.

설정적용 범위이 셋 사이의 우선순위
system시스템의 모든 사용자·저장소낮음
global현재 OS 사용자의 여러 저장소중간
local현재 저장소높음

기존 TIL의 AI 보충 설명에서는 같은 항목에 local 값이 있으면 그 값을 우선 사용한다고 구분했다. 다른 설정 파일을 지우거나 값을 가져온다는 뜻은 아니다. Git에는 다른 설정 출처도 있으므로 이 표를 모든 설정 출처의 전체 순서로 보지는 않는다.

작업 폴더·스테이징·커밋

파일을 편집하는 것, 다음 커밋에 담을 변경을 고르는 것, 버전으로 기록하는 것을 나누어 정리했다. 복습 메모에는 설정 출처 출력과 작업 폴더 경계 확인 결과가 남아 있다. 개인정보·개인 경로가 포함된 실제 출력 전체는 이 글에 복제하지 않는다.

확인되지 않은 문제는 별도로 남겼다

PowerShell에서 uv 설치 후 버전 확인 명령이 실행되지 않아 원인을 질문했다. PATH 문제는 당시 AI의 추정이었고 수정 성공은 확인되지 않았다. 이 문제를 Git 설정 학습의 해결 성과와 섞지 않는다. SSH와 PAT의 차이도 추가 확인 대상으로 남아 있다.
