실습 환경과 안전 범위

PC 터미널에서, 원격 연결이 없고 버려도 되는 새 연습 저장소만 사용한다. 실제 프로젝트에서 reset --hard를 시험하지 않는다. Python 실행창용 코드가 아니다.

1. ignore와 추적 상태 비교

가짜 로그 파일을 만들어 .gitignore 규칙 적용 전후를 비교한다. 처음 만든 파일과 이미 추적한 파일을 나누어 git status --ignored, git ls-files 파일명, git check-ignore -v 파일명의 차이를 설명한다. 출력이 없을 때도 다른 명령으로 상태를 함께 확인한다.

2. 한 커밋과 두 시점의 차이

두 번의 작은 텍스트 변경을 각각 커밋한다. git log --oneline에서 메시지와 ID를 확인하고, git show ID와 git diff 이전ID 이후ID가 각각 무엇을 보여주는지 기록한다.

3. 되돌리기 결과 먼저 예측

같은 출발 상태에서 soft·mixed·hard가 HEAD·인덱스·작업 파일에 미치는 영향을 표로 예측한다. 원본 변경을 잃을 수 있는 명령은 실습용 저장소 외에서 실행하지 않는다. revert가 기존 이력을 이동하는지, 취소 커밋을 추가하는지도 비교한다. 여기에는 아직 수행 결과가 없다.
